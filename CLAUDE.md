# HAL website — Ashley Lim

Marketing site for Ashley Lim (애슐리 림) and her programs, starting with 내성만방 (NSMB).
Korean-first copy, long-form sales pages, deployed on Vercel from GitHub.

- Repo: https://github.com/heyashleylim/hal-website (`main` = production)
- Hosting: Vercel. Push to `main` → production deploy. Any other branch → preview URL.
- Stack: static HTML + CSS + vanilla JS. No framework, no build step.
  npm is used **only for the API functions** (`package.json`: the Neon database driver and `@vercel/blob`, approved 2026-10-23 for the private podcast).
  Pages in `site/` never import npm packages. Do not add a framework, a build step or another dependency without asking first.

Rules for the structure:
- Anything in `site/` is public. Docs, drafts, source files and notes never go there.
- One page = one folder with an `index.html`. Shared code lives in `site/assets/`, never copied per page.
- Page-specific CSS stays in a `<style>` block in that page only while it is small. Once two pages need it, move it to `components.css`.
- Asset paths are root-relative (`/assets/img/...`) so they work from any page folder.
- Filenames: lowercase, kebab-case, ASCII only (`nsmb-review-cho.webp`, not `내성만방-review-CHO-Small.png`). Korean filenames break URLs and caching.

## Source of truth (in this order)

1. **Ashley's copy** (`docs/content/`, or the live page it came from). Words, prices, dates and testimonials are hers.
2. **`docs/DESIGN.md`**: colors, type, spacing, components for the web. Tokens in `site/assets/css/tokens.css` must match it.
3. **Skills**: they advise. When a skill and DESIGN.md disagree, DESIGN.md wins. Flag the conflict instead of silently choosing.

`FRAME.md` is for video frames (1920×1080, 1080×1920, 1080×1080). Use it for reels, covers and thumbnails, not for page layout.

## Skills: when to use which

- **frontend-design**: new pages or sections, and any time the aesthetic direction is open. Use it to make choices that feel intentional, then express them through DESIGN.md tokens.
- **ui-ux-pro-max**: focused checks and fixes, such as accessibility, contrast, touch targets, forms, responsive layout, motion and the pre-delivery checklist. Query one concern at a time (`--domain ux`, `--stack html-tailwind` for HTML/CSS patterns). Do not let `--design-system` replace DESIGN.md.
- **ashley-lim-voice / ashley-lim-market**: any new or edited Korean copy, testimonial selection, persona or offer questions.
- **ashley-lim-design**: quick reference for Ashley's brand tokens. If it differs from DESIGN.md, ask.

## Content rules (non-negotiable)

- Never invent testimonials, numbers, results, prices, deadlines, guarantees or names. Use only what Ashley has published or provided.
- Keep testimonial text verbatim, including emoji and informal spelling. Anonymized names stay anonymized (`김00`).
- If source copy contradicts itself (for example two different refund periods on one page), keep it and flag it. Don't fix it silently.
- Structural labels (eyebrows, section tags) may be added for design, but list them in the change summary.
- Legal/business footer details (사업자등록번호, 통신판매업신고, address) must match the live ashleylim.com footer exactly.

## Code conventions

- **Tokens only**: components use CSS variables (`var(--accent)`), never raw hex.
- **"Accent color" = Vermilion `#DB4A2B`** (`--accent`, hover `--accent-hover` `#F16344`). Whenever the accent color is mentioned, use this — never the dusty rose `--rose` `#C37568` or the ENGINE red `#bd1b1b`.
- **Korean typography**: `word-break: keep-all`; body line-height ≥ 1.6; no positive letter-spacing on Hangul (Latin-only labels may track out); never fake-italicize Korean (`font-synthesis: none` on `em`).
- **Fonts**: pages in Ashley's style use the self-hosted subsets in `site/assets/fonts/` via `brand.css` (KS X 1001 Hangul + Latin + symbols; full originals live in `_originals/fonts/`). If new copy uses a rare Hangul syllable outside that set, re-run the subset with the extra characters. `/engine` still loads its ENGINE fonts from Google Fonts / Fontshare / jsDelivr.
- **Images**: WebP (JPEG fallback only if needed), explicit `width`/`height`, `loading="lazy"` below the fold, `fetchpriority="high"` on the hero only. Max ~300 KB each, ~2000px on the long edge.
- **Video**: lite-YouTube pattern (thumbnail + play button, iframe on click, `youtube-nocookie.com`). No autoplaying embeds.
- **JS**: vanilla, progressive enhancement. The page must read correctly with JS off (reveals default to visible).
- **Motion**: transform/opacity only, and respect `prefers-reduced-motion`.
- **Accessibility**: one `h1` per page, sequential headings, visible focus rings, labels on every input, 44px touch targets, text contrast ≥ 4.5:1, skip link.
- **Responsive**: check 375px, 768px, 1024px and 1440px. There must be no horizontal scroll at 375px.
- **Third parties**: no new trackers, pixels, chat widgets or CDNs without asking. Fonts may come from Google Fonts or jsDelivr only until self-hosted.
- **Google Tag Manager** (`GTM-MK4FNWNV`, asked for by Ashley) is on every public page, never on `/preview/*`, `/admin/*` or the private podcast pages (`/podcast/*`, feeds, audio: a student's secret token is in those URLs): head script right after `<meta charset>`, `<noscript>` iframe right after `<body>`. `tools/rebuild/gtm.py` adds it (gen.py runs it; run it on any new hand-built page). Tags, pixels and analytics are managed in GTM, not in this repo.
- **Vercel Web Analytics** is enabled in the Vercel project and loaded on the same public pages as GTM (never `/preview/*`, `/admin/*` or the private podcast pages): `window.va` queue + `<script defer src="/_vercel/insights/script.js">` right before `</head>`. `tools/rebuild/gtm.py` adds both (gen.py runs it). Locally the script 404s; that's expected.

## Generated pages and private previews

- `/lifeartist` (from the live `/lifeartist2026`; the old URL redirects in `vercel.json`), `/eft`, `/chosen`, `/switch` and the three policy pages are **generated** by `tools/rebuild/` from captures of the live pages. Each has its CSS inline, with one class per style combination. **Don't hand-edit them**: when the live page changes, re-capture and regenerate (see `tools/rebuild/README.md`). If a page here should diverge from the live site, hand-build it like `/nsmb` instead.
- `/preview/<page>` shows the same page **including elements hidden on the live site**, outlined in rose with a "숨김 · 데스크톱/태블릿/모바일" tag. Images used only by hidden elements live under `/preview/<page>/img/`, so they're protected too.
- Previews are protected by `middleware.js`: any `/preview/*` URL shows a login page (아이디 / 비밀번호), and a correct login sets an HttpOnly cookie for `/preview` valid 30 days. Changing `PREVIEW_PASSWORD` logs everyone out. Don't switch back to the browser's Basic Auth pop-up: its credentials don't reach the middleware behind Vercel's deployment protection. `PREVIEW_USER` and `PREVIEW_PASSWORD` are set in Vercel (all environments). Without them `/preview/*` returns 503 for everyone. They're also `noindex` (meta + `X-Robots-Tag`) and disallowed in `robots.txt`.
- Every FAQ uses the /nsmb accordion style (`faq.css`): the generator rebuilds each live accordion as `<div class="faq"><details><summary>…<span class="pm"></span></summary><div class="ans">…</div></details></div>`, keeping the live questions and answers word for word.
- Deliberate differences from the live pages (asked for by Ashley) live in `tools/rebuild/overrides.json` so they survive regeneration. Currently: equal-height EFT cards ("수업이 끝나면, 이렇게 달라집니다") at every width; the EFT review screenshots as a masonry (3 columns desktop, 2 tablet, 1 phone, including the large review that sits below the grid on live); extra space after the FAQ on /switch and /lifeartist and after the last section of the policy pages; the /lifeartist plan hover outline (live behaviour the capture can't record); Korean words never split across lines on every generated page (`keep_words`); slimmer one-line buttons on /eft phones; 20px side padding on the policy pages below 1025px.
- Every page except home uses the same main header: the `<header class="site-header">` markup from `site/nsmb/index.html` plus `header.css` (sticky, 60px, 1px #D7D7D7 bottom rule, logo linking to ashleylim.com). The generator copies it into each generated page without /nsmb's button; pages whose live header has a button (`/eft`, `/chosen`) keep theirs, with its live look, linking to the price section on the same page. Change the header in `site/nsmb/index.html`, then regenerate.
- Every page uses the same footer: the `<footer class="site-footer">` markup from `site/index.html` plus `footer.css`. The generator copies that markup from the home page each time it runs, so change the footer in `site/index.html` (and `/nsmb`), then regenerate the generated pages.
- Every link to an ashleylim.com page is a site path (`/eft`, `/refund-policy`, `/` for the logo; `/lifeartist2026` → `/lifeartist`) and opens in the same tab, so links follow whatever domain serves the site (www.ashleylim.com). Only payment links keep `https://ashleylim.com/?product=…`: add-to-cart links into the WooCommerce / cafe24 checkout, which stays on WordPress at ashleylim.com. `tools/rebuild/sitelinks.py` does this (gen.py runs it; run it on hand-built pages after pasting live links).
- Public pages carry `<link rel="canonical">` naming the page on `https://www.ashleylim.com` (this site, once the domain moves to Vercel).

## Private podcast

Private podcasts for Ashley's programs: several **shows**, each with cohorts (weekly drip, 1-year access). A **student**
(one per email) has one personal page listing their shows and is **enrolled** in any number of cohorts, including several
of the same show (they get every episode any running enrolment releases; access lasts until the latest end).
ActiveCampaign automation and admin pages.
Plan, decisions and phases: `docs/podcast-plan.md`. Built on the `podcast` branch.
- Data lives in Neon Postgres (`DATABASE_URL`), never in the repo (it is public). All SQL goes through `api/_lib/db.js`.
- Previews use their own Neon branch (`PODCAST_DATABASE_URL`, set for Preview only; without it the preview admin refuses
  changes). Run `npm run db:migrate` and `npm run db:migrate:preview` after adding a migration. Both share one Blob store:
  previews upload under `preview/` and can't delete production's files.
- Release and access rules are in `api/_lib/release.js` (pure, unit-tested). Change them there and in its tests only.
- **One admin for the whole site** at `/admin` (its own login in middleware; `/api/admin` checks the same cookie itself).
  Home `/admin` (sections + system status), global `/admin/activity`, and one folder per section: `/admin/podcast/`
  (Overview, `episodes/`, `cohorts/`, `students/`, `programs/`, `automation/`). Later sections (e-commerce…) get their own
  folder. Navigation is on the left, like ActiveCampaign's admin: a dark teal icon rail (always visible: Home, sections,
  Activity, Log out) and the current section's collapsible menu (grouped links; Podcast adds the program switcher). Content is on
  white. Drawn by `site/assets/js/admin/admin.js` (SECTIONS and ICONS; pages use `<body data-section="…">` and an empty
  `<header class="admin-bar">`); styles in `assets/css/admin/admin.css`.
  Every admin button has a `data-tip` saying what it does (shown as a tooltip by admin.js; `npm test` fails without it). API: `api/admin.js` routes actions from
  `api/_lib/admin/system.js` (health, activity) and `api/_lib/admin/podcast-*.js` (content, cohorts, students, automation);
  a new section adds its module there (unique action names). `admin_log` records each action's section.
- "Access until" dates shown anywhere are the last listening day: access ends at 00:00 KST the day after.
- Uploads go straight from the browser to the private Blob store through a short-lived signed URL (`upload-url`), so
  there's no 4.5 MB function limit. Cover art is served publicly at `/a/art/<show>.<ext>`.
- The admin API only runs on Vercel deployments: the local `site` preview serves static files only.
- Student URLs (rewrites in `vercel.json`, token = the student's 22 random characters): `/podcast/<token>` personal page
  listing their shows (api/podcast-page.js, header/footer read from `site/nsmb` and `site/index.html` at runtime),
  `/f/<token>/<show slug>` one feed per show (`/f/<token>` still works for students with one show), `/a/<token>/<guid>.mp3`
  audio streamed from the private Vercel Blob store. `/podcast/help` is a static page. All are noindex and in robots.txt.
- In the admin, a show is called a **program** (the data model and code say `show`). The program switcher (left menu) scopes
  Episodes, Cohorts, the Programs page, imports and the AC sync; the Students page covers all programs. A cohort's AC tag
  is unique across programs.
- The AC sync names students from the contact's **First name** only: Ashley's team keeps the full Korean name (e.g. 김지연) there.
- ActiveCampaign automation (`api/_lib/automation.js`, page `/admin/podcast/automation`): the site never calls AC during a
  student's request; it queues updates in `ac_outbox` (dedupe keys: each tag once per student and program) and sends them
  right after admin actions/webhooks, on "Send pending now", or in the daily job (`vercel.json` crons, 09:10 KST,
  production only, `CRON_SECRET`). Webhook `POST /api/podcast-ac?key=…` (key derived from PODCAST_SECRET) enrols on purchase
  tags (set up as AC's account webhook "Contact Tag Added": it fires for every tag, non-cohort tags are ignored); `&action=revoke&tag=…` for refunds. Tags per program (underscores, like Ashley's other AC tags): `<prefix>_enrolled`,
  `_subscribed`, `_not_subscribed_3d/7d`, `_epNN_released`, `_epNN_downloaded`, `_completed`, `_expiring_30d`, `_expired`,
  `_revoked` (prefix e.g. `podcast_nsmb`), plus `podcast_link_reset`; field `PODCAST_LINK`.
  Students added by hand only reach AC when "Tell ActiveCampaign" is ticked.

## Shop (e-commerce, replacing WooCommerce)

Plan, decisions and phases: `docs/commerce-plan.md` (phase table at the top; section 10 = the checkout as built and
Alex's real-payment tests). Built on the `shop` branch. Phase 1 (products, orders, tax ledger) and phase 2 (checkout,
pay in full) are built. The site's payment links still go to WordPress until go-live (phase 5).
**This code takes real money: every change needs `npm test` and `npm run test:shop` to pass, and a browser check.**
- Pages: `/checkout/<product>` and `/checkout/complete` (rewrites in `vercel.json` → `api/shop-page.js`), rendered on the
  server by `api/_lib/shop/page.js`, in Korean (`copy.ko.js` holds every customer-facing string), `noindex`, with GTM.
  `/checkout`, `/checkout/order-received/*` and `/checkout/order-pay/*` still redirect to WordPress; a product can't use
  those addresses or `complete`.
- Admin section `/admin/shop/` (Overview, `orders/`, `products/`, `settings/`); API modules `api/_lib/admin/shop-*.js`,
  actions prefixed `shop-`.
- Money is a whole number in the smallest unit (won; cents for USD), VAT included. **Every amount is computed on the
  server by `api/_lib/shop/pricing.js`** (pure, unit-tested); the browser never sends an amount. Change price rules there
  and in `tests/shop/` only.
- KRW → CiderPay (hosted payment page, then a "feedback" notice to `/api/shop-callback?p=ciderpay&k=…`). USD → PayPal
  (redirect, capture on return to `/checkout/complete`, webhooks as a safety net). No PayPal script on the page.
  CiderPay has no test mode and no payment lookup: a notice is believed only with the address key, the order token and
  our signature (`pay/ciderpay.js`), and the exact amount (`orders.decide`).
- A payment is recorded once, with its ledger line and the order state, by one statement (`orders.recordPayment`;
  unique `(provider, kind, provider_ref)`). Opening the thank-you page never marks an order paid. A second, different
  payment for an already-paid order is held (logged as `extra` in `shop_callbacks`, Slack alert), never recorded.
- Production always uses PayPal live (`PAYPAL_ENV` only applies to previews). The shop refuses to run on a preview
  without its own database (`db.separateFromProduction()`). Only payment methods with keys present are offered.
- `shop_ledger` is the tax record: one permanent line per payment or refund (supply + VAT), built by
  `api/_lib/shop/ledger.js`. A database trigger refuses edits and deletes (only a USD line's exchange-rate columns can
  change); a correction is a new line. Orders, payments and ledger lines are never deleted automatically.
- ActiveCampaign: `shop_outbox` (own queue, like the podcast's), sent by `sync.js` after a payment, from the thank-you
  page, by "Send to ActiveCampaign now" in the admin, and by the daily cron. A product's purchase tag is the one
  WooCommerce used (`purchased_eft`, `purchased_chosen_2026`, `purchased_switch`, `purchased_nsmb_XX_YYYYMM`), set per
  product. Order fields (`ORDER_NUMBER`…) that don't exist in AC are skipped, never blocking the tags.
- **Add-ons** (order bump, Alex 2026-11-13; Marie Forleo's "Popular add-ons" style, layout from the Copy Cure checkout):
  an add-on is a product of its own (prices, optional crossed-out regular price `compare_krw/usd`, tags,
  `content.addon_details` / `addon_note`); a product lists the add-ons its checkout offers (`addon_ids`, max 6);
  `addon_only` products have no checkout of their own. The form sends `addon_<id>` ticks; `flow.start` refuses an add-on
  that isn't offered right now (`addon_unavailable`) rather than dropping it. An order's items (`shop_order_items`) add
  up to its total; its payments get one tax ledger line per VAT rule (`ledger.lines`). Each add-on's purchase tag is
  added in AC. Not with instalment plans yet.
- **Checkout page** (Alex 2026-11-14): Copy Cure layout without its logo. Left (below the form on a phone), as text on
  the page background: name, summary, picture, what's included (`content.included` = `[{ title, text }]`, heading
  `content.included_title`), guarantee, reviews. Right, the form: 내 정보 → 주소 (country first, Korea by default; the
  Kakao search only for a Korean address) → 옵션 선택 (only with pricing options) → 결제 방법 (신용/체크카드 = KRW/CiderPay,
  PayPal = USD; only the methods with keys) → add-ons → order → button. The method sets the currency: every price is
  written in both (`[data-cur]`) and `checkout.js` shows the one picked. Without JavaScript, a form posted with another
  method than the prices shown (`shown_currency`) comes back once in that currency (`currency_changed`) before paying.
- **Pricing options** (Alex 2026-11-14): `shop_products.price_options` = none or 2–6 `{ key, label, note, price_krw,
  price_usd, compare_krw, compare_usd, tag }`; every option carries the same currencies; the product's own prices are the
  first option's (set by the admin). The form sends `option=<key>`; an order of a product with options must name one
  (`option_unavailable` otherwise). The order keeps `{ key, label, tag }` in `shop_orders.price_option`, its main item
  is named "product · option", and the option's tag is added in AC with the product's. Not with instalment plans yet:
  they join the same picker in phase 3.
- Instalment plans are stored on products but not sold yet (`orders.INSTALMENTS_ENABLED`, phase 3). The refund window is
  14 days; refunds are handled by hand until phase 3.
- Env vars: `SHOP_SECRET` (never change once live), `CIDERPAY_*`, `PAYPAL_*`, `SLACK_WEBHOOK_*` (`.env.example`).
  Previews use the PayPal sandbox and need Vercel's "Protection Bypass for Automation" so providers can reach them.
- The Kakao address search loads from `t1.kakaocdn.net` with no parameters (the script refuses any, with an alert).
- Local testing with nothing saved and no money: the `shop-admin` preview (`tools/shop/dev-server.js`, port 8793) runs
  the site, the admin and the checkout against fake CiderPay/PayPal inside one transaction that is rolled back when it
  stops (pending migrations are applied inside it; it uses `PODCAST_DATABASE_URL` when set). Only one can run at a
  time: stop it before `npm run test:shop`, which uses the same mechanism.

## Page configuration

Sales pages keep cohort-specific values in one place: the `data-state` and `data-deadline` attributes on `#page`.

- `data-state="open" | "closed"`: closed shows the waitlist and the "registration closed" notices.
- `data-deadline`: ISO date with `+09:00` (KST). After it passes, the page switches to closed on its own.
- Preview either state with `?enroll=open` / `?enroll=closed`.

**Timed sales on generated pages (e.g. /eft):** `"sale"` in `tools/rebuild/overrides.json` sets the deadline (KST), the texts that disappear at the deadline, the price that changes and where the countdown goes. `site/assets/js/sale.js` shows the countdown and switches the page in the browser at the deadline (test with `?sale-now=2026-10-17T00:00:00%2B09:00`); `.github/workflows/sale-end.yml` then runs `tools/rebuild/sale_end.py` just after it and pushes the regular version, so the HTML itself changes too. The WooCommerce price is scheduled in WordPress (product → Sale price → Schedule), with the same end date and the WordPress timezone set to Seoul. For a new sale: update `"sale"`, regenerate the page, and change the cron line in the workflow (UTC).

**New cohort checklist:** deadline, prices, payment links, refund-request date (guarantee section and FAQ), live-session count/day, waitlist form endpoint, `og:` image, footer year.
